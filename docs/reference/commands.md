# Commands

## Slash commands

Type `/pulse` in Claude Code, in the terminal or the IDE; autocomplete lists the rest. In Codex, type `$pulse:pulse`, in the CLI and the IDE extension alike; the Codex CLI also lists the skills under `/skills` > **List skills**, or as soon as you type `$`, by the names `pulse-ba (pulse)` and so on, the IDE extension under **Skills** when you type `/` in the prompt box. Support for GitHub Copilot, Cursor, Gemini CLI, and OpenCode will follow. Each command is its own skill and can be called on its own; in the Pulse flow they hand over to each other without asking and stop only [where a person decides](../concepts/v-model#where-pulse-stops-for-you). `/pulse-build` builds one item in your session, `/pulse-go` runs the same build for every ready item in parallel.

## The pulse command line

Every deterministic step is a script, so no model has to do bookkeeping. The Pulse hooks tell the agent where the CLI lives. For your own terminal, `pulse setup --cli` puts the `pulse` command in `~/.local/bin`, once per machine ([Installation](../tutorials/installation)); `/pulse-setup` offers the same. Python 3.9 or newer, standard library only.

Reads come from a local cache (`--fresh` skips it); `--json` gives machine-readable output. Exit codes: 0 done, 1 refused, 2 cannot act here (no repository, ambiguous remotes, `gh` failed, a spec for `pulse new --spec` that is missing or not on origin).

### Plumbing

For skills, hooks, and `pulse go`; `pulse --help` lists them apart.

| Command | Does |
|---|---|

| `pulse block <n> --by <by>` | item n waits until the given items are done<br>`--by <by>`: comma-separated item numbers |
| `pulse review [<n>]` | a fresh session reviews an item's branch or any scope<br>`[<n>]`: the item; its verdict is kept for its PR<br>`--scope full\|branch\|commit\|working\|staged\|range`: default: branch with an item, else working (the current work)<br>`--base <base>`: the branch scope measures against this ref (default: the base branch)<br>`--range <range>`: A..B for --scope range<br>`--run`: start the session headless and read its verdict<br>`--record`: keep the REVIEW.md a subagent wrote<br>`--publish`: put the kept review and audit verdicts for HEAD on the open PR of this branch<br>`--agent <agent>`: agent template from [agents] (default: review_agent, else agent)<br>`--json` |

## pulse check

| Rule | Checks |
|---|---|
| C1 | relative Markdown links in `_devprocess/` and agent guides resolve |
| C2 | backticked repository paths in agent guides (AGENTS.md, CLAUDE.md, the system map, the decisions router) exist |
| C3 | no code paths in the core sections of a decision record |
| C4 | no work state (`status`, `phase`, `claim`, ...) in any `_devprocess` frontmatter |
| C5 | artifacts stay within their line cap plus 10% (an epic's `## Items` list does not count), unless they state a reasoned exception (`## Reasoned exception`, the heading in any case) |
| C6 | every feature spec has an Activation Path with Type and Identifier |
| C7 | every `FIXME(stub):` in the code names an item, an open one when the cache knows |
| C8 | tasks in one wave of a PLAN touch disjoint files |
| C9 | every spec's `parent:` and its epic's `## Items` list agree |
| C10 | every spec's file name starts with the ID its place in the tree calls for (`EPIC-04`, `FEAT-04-02`, `FIX-04-02-01`); `pulse number --apply` fixes what it reports |
| R1 to R6 | an approved item's spec is one an agent can plan from, read from the base branch (see [/pulse-re](../guides/pulse-re#quality-gates)) |

Files under `_devprocess/temp/` are not checked: temporary test files live there only until they are deleted.

`pulse setup --git-hook` runs it before every commit, together with a guard against commits on protected branches.
